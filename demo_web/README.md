# บ้านรอด AI: คู่มือส่งต่อ

สถานะ ณ 16 ต.ค. 2026 ตี 1 · ส่งงานบ่าย 2 วันเดียวกัน

เว็บแอปมือถือสำหรับคนรายได้ไม่แน่นอน บอกตัวเลขเดียวทุกวันว่า "วันนี้ใช้ได้อีกเท่าไหร่" ทำงานในเบราว์เซอร์ทั้งหมด ไม่มีเซิร์ฟเวอร์ ไม่มีบัญชีผู้ใช้ ข้อมูลเก็บใน localStorage ของเครื่องนั้น

## เริ่มใน 2 นาที

```bash
python3 build.py              # รวมไฟล์เป็น dist/index.html
node test.js                  # เครื่องคำนวณงบ + ตัวอ่านสลิป (19 ข้อ)
node rules.test.js            # กฎจัดหมวด (63 กรณี)
npm i jsdom && node smoke.test.js   # กดตามเดโมแบบไม่เปิดเบราว์เซอร์ (ไม่บังคับ)

cd dist && python3 -m http.server 8000
# เปิด http://localhost:8000 หรือ http://<IP เครื่อง>:8000 บนมือถือ (Wi-Fi เดียวกัน)
```

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ ห้ามดับเบิลคลิกเปิดไฟล์ OCR โหลดภาษาไทยจากเน็ตตอนใช้ครั้งแรก ก่อนเดโมให้กด "เตรียม OCR ล่วงหน้า" ในแท็บเพิ่มสลิปบนเครื่องที่จะใช้จริง

**ห้ามแก้ `dist/index.html` ตรงๆ** ให้แก้ไฟล์ต้นทางแล้วรัน `python3 build.py` ใหม่ ยังไม่ได้เอาขึ้น GitHub (เจ้าของงานยังไม่อยากเผยแพร่)

## ไฟล์

| ไฟล์ | ทำอะไร |
|---|---|
| `shell.html` | หน้าตา: CSS (สีสว่าง/มืด), โครงหน้า, แท็บล่าง มีที่วาง `/*ENGINE*/` และ `/*APP*/` |
| `engine.js` | เครื่องคำนวณงบ (`replay`), ตัวอ่านข้อความสลิป (`parseSlip`), หาร้านที่จำ (`findShop`, `learnAlias`) ฟังก์ชันล้วน ทดสอบใน Node ได้ |
| `rules.js` | ตารางกฎจัดหมวด 27 กลุ่ม + `classify()` ที่บอกเหตุผล เพิ่มร้านหรือคำใหม่ได้ที่นี่ |
| `app.js` | หน้าจอ 4 แท็บ (วันนี้ / เพิ่มสลิป / ร้านที่จำ / ตั้งค่า), OCR ด้วย Tesseract.js, เก็บข้อมูล |
| `test.js`, `rules.test.js`, `smoke.test.js` | ชุดทดสอบ |
| `build.py` | รวมทุกไฟล์เป็น `dist/index.html` |

## โฟลวที่ 1: สลิป → รายการ

1. **เลือกรูป** (`<input type=file>`) แล้ว OCR ด้วย Tesseract.js 5.1.1 ภาษา `tha+eng` บนเครื่อง รูปไม่ถูกส่งออกไปไหนและไม่ถูกเก็บ
2. **`parseSlip(text)`** แยกข้อมูลได้ `amount, date, sender, shop, acct, memo, candidates`
   - ยอด: ตัวเลขทศนิยม 2 ตำแหน่ง เลือกบรรทัดที่มีคำว่า จำนวน/ยอด/บาท ก่อน และข้ามบรรทัดค่าธรรมเนียม
   - วันที่: เดือนไทยแบบย่อ ปี พ.ศ. 2 หลัก (69 → 2026) หรือรูปแบบ dd/mm/yyyy
   - ผู้รับ: บรรทัดหลัง "ไปยัง/ถึง/To" → บรรทัดก่อน "รหัสร้านค้า" → ชื่อสุดท้ายที่ตามด้วยบรรทัดธนาคาร/เลขบัญชี
   - ผู้ส่ง: บรรทัดหลัง "จาก/From" หรือชื่อแรกที่ตามด้วยบรรทัดธนาคาร
   - เลขบัญชี: **เฉพาะบรรทัดใต้ชื่อผู้รับไม่เกิน 2 บรรทัด** (สลิปพร้อมเพย์/QR จะได้ค่าว่าง ห้ามหยิบเลขบัญชีบรรทัดสุดท้าย เพราะจะได้เลขของผู้ใช้เอง ซึ่งเคยเป็นบั๊กที่ทำให้ร้านใหม่ถูกจำเป็นร้านเก่า)
   - บันทึกช่วยจำ: บรรทัด "บันทึกช่วยจำ/Memo/หมายเหตุ" หรือบรรทัดถัดไป
   - บรรทัดที่ OCR เว้นวรรคถี่ผิดปกติจะถูกยุบช่องว่างระหว่างตัวไทย บรรทัดปกติคงช่องว่างไว้
3. **`findShop`** หาร้านที่จำไว้ตามลำดับ: ชื่อตรง → ชื่อที่เคยอ่านเพี้ยนแล้วแก้ไว้ → เลขบัญชี (ใช้เองเฉพาะเมื่ออ่านชื่อไม่ได้เลย) ถ้าอ่านชื่อได้แต่ไม่รู้จัก = ร้านใหม่ ถ้าเลขบัญชีตรงกับร้านเก่า แอปขึ้นเป็นปุ่ม "ใช่ ร้าน X" ให้ผู้ใช้กดยืนยันเอง
4. **`classify`** ไล่กฎ ข้อแรกที่เข้าได้ชนะ:
   1. ทิศทางเงิน: เทียบชื่อผู้ส่ง/ผู้รับกับ `settings.owners` (ทนชื่อที่ธนาคารปิดบางส่วน) ผู้รับคือเจ้าของ = `income` ทั้งคู่คือเจ้าของ = `transfer`
   2. บันทึกช่วยจำระบุหมวดตรงๆ เช่น "ค่ากิน" หรือ "#เดินทาง"
   3. บันทึกช่วยจำเข้ากฎคำหลัก
   4. ความจำร้าน
   5. ชื่อร้านเข้ากฎคำหลัก (ข้ามข้อนี้ถ้าผู้รับมีคำนำหน้าชื่อคน)
   6. โอนให้บุคคล / ไม่รู้จัก → `other` ความมั่นใจต่ำ ให้ผู้ใช้เลือก
5. **หน้าตรวจ** ให้แก้ยอดได้ แตะเลือกชื่อร้านจากบรรทัดที่อ่านได้ ถามโน้ตร้านใหม่ครั้งเดียว และแสดงเหตุผลของหมวด
6. **บันทึก** แล้วจำร้าน ทางลัดชื่อที่เคยแก้ และทางลัดเลขบัญชี (`learnAlias`: ถ้าทางลัดเดียวกันเคยชี้ไปคนละร้าน จะลบทิ้งและห้ามใช้อีก ไม่สร้างทางลัดจากชื่อเจ้าของ)

หมวด: `shop, coffee, travel, other, food` (ปรับงบได้) · `fixed` ค่าคงที่ · `transfer` โอน/ออม · `income` รายรับ สามหมวดหลังไม่หักงบรายวัน

## โฟลวที่ 2: เครื่องคำนวณงบ (`engine.replay`) คำนวณด้วยโค้ดล้วน ไม่ใช้ AI

```
M (ถังรายเดือน) = รายได้ − ค่าคงที่ − ขั้นต่ำบัตร − เงินสำรอง
B (งบฐาน)       = floor(M / จำนวนวัน) แบ่งหมวดตามสัดส่วน เศษให้หมวดท้ายลำดับ
T (งบวันนี้)     = B − C + เงินยกมา   โดย C = min(ยอดค้าง D, ผลรวมเพดานลด) ลดตามลำดับหมวด
ปิดวัน: ใช้ U > T → D = D − C + (U − T)
        ใช้ U ≤ T → D = D − C และ T − U เข้าถังสำรอง (หรือยกไปพรุ่งนี้ตามตั้งค่า)
รายได้จริงเปลี่ยน: B = floor((M ใหม่ − ใช้ไปแล้ว − ถังสำรอง) / วันที่เหลือรวมวันนี้), D = 0
ลดเต็มเพดานแล้วยังขาด: ยกยอดค้างไป ผู้ใช้กดปุ่ม "ใช้ถังสำรองปิดยอดค้าง" เอง
```

`replay` คำนวณใหม่ตั้งแต่วันแรกทุกครั้งจากรายการทั้งหมด ไม่มีสถานะที่แก้ทีละวัน จึงลบหรือแก้รายการย้อนหลังได้โดยไม่พัง หนี้บัตร: ขั้นต่ำนับเป็นค่าคงที่ ส่วนยอดหนี้และดอกเบี้ยใช้แสดงผลเท่านั้น (ดอกต่อเดือน = ยอด × % ต่อปี ÷ 12)

ตัวเลขทดสอบ (ชุดตั้งต้น 20,000 / ค่าคงที่ 8,000 / สำรอง 2,000 / 30 วัน / หมวด ช้อปปิ้ง 83 (ลดได้ 100%) → กาแฟ 50 (50%) → ค่ากิน 200 (50%)):
T1 B = 333 · T2 ใช้เกิน 100 → วันที่ 2 ได้ 233 (ลดช้อปปิ้ง 83 + กาแฟ 17) · T3 เหลือ 100 → ถังสำรอง 100 · T4 วันที่ 10 รายได้เป็น 17,000 → B = 190 · T12 ขั้นต่ำบัตร 1,500 → B = 283, หมวด 70/42/171 · T8 ผลรวมหมวด = T เสมอ

## ข้อมูลใน localStorage (คีย์ `banrod-v1`)

`settings` (รายได้, ค่าคงที่, debt, owners, cats พร้อม weight/cap เรียงตามลำดับลด) · `txns` [{day, amount, shop, cat, source, memo}] (`day` = เลขวันนับจาก startDate) · `shops` {shopKey: {name, cat, note}} · `aliases` {shopKey หรือ 'acct:เลข': shopKey, `__shared`: ทางลัดที่ห้ามใช้} · `incomes` [{day, amount}] · `covers` [{day}] · `offset` (ปุ่มข้ามวันสำหรับเดโม)

## สิ่งที่ยังไม่ได้ทดสอบ หรือยังอ่อนอยู่

- **OCR กับสลิปจริงยังทดสอบน้อย** ตัวอ่านผ่านแค่ข้อความตัวอย่าง เจ้าของงานเจอชื่อร้านอ่านเพี้ยนในสลิปจริงบ้างแล้ว ถ้าเจอรูปแบบใหม่ ให้กด "ดูข้อความที่ OCR อ่านได้ → คัดลอก" ในหน้าตรวจ แล้วเพิ่มเป็นกรณีทดสอบใน `test.js` ก่อนแก้ `parseShop`
- ชื่อที่อ่านเพี้ยนต้องเพี้ยนแบบเดิมทุกตัวอักษรถึงจะจำได้ ยังไม่มีการเทียบชื่อแบบใกล้เคียง (ตั้งใจไม่ใส่ เพราะร้านชื่อคล้ายกันจะถูกจำรวมกัน)
- ยังไม่มี LLM ทั้งการจัดหมวดและประโยคอธิบายเป็นกฎ/แม่แบบล้วน (ตรงกับทางสำรองในแผนข้อ 9)
- ในหน้า artifact ของ Claude OCR ใช้ไม่ได้เพราะถูกบล็อกการโหลด ต้องใช้ `dist/index.html` ผ่านเว็บเซิร์ฟเวอร์

## สคริปต์เดโม (ไม่เกิน 3 นาที)

1. ปัญหา: คนรายได้ไม่แน่นอน แต่แอปจดเงินทั่วไปคิดว่าเงินเข้าเท่ากันทุกเดือน
2. เพิ่มสลิป: สลิปร้านตามสั่ง → ร้านใหม่ถามโน้ตครั้งเดียว → ใบถัดไปจำได้ (ไม่มีเน็ตใช้ "สลิปตัวอย่าง" แทน)
3. สลิปโอนให้เพื่อนมีบันทึกช่วยจำ "ค่าข้าวเย็น" → ลงหมวดค่ากิน · เพื่อนโอนคืน → แอปรู้ว่าเป็นรายรับ ไม่หักงบ
4. หน้าวันนี้: "วันนี้ใช้ได้อีก ฿…" + "ทำไมได้เท่านี้"
5. แกนชูโรง: ใส่รายได้จริง 14,000 → งบลดทันทีพร้อมเหตุผล · ใช้เกินแล้วกด "ปิดวันนี้" → พรุ่งนี้ลดหมวดตามลำดับ ค่ากินถูกแตะเป็นลำดับท้าย
6. ใครถามว่าตัวเลขมาจากไหน: เปิดการ์ด "ที่มาของงบ" และหน้า "ตรวจกติกา" ในตั้งค่า

ก่อนเดโม กด "โหลดข้อมูลตัวอย่างใหม่" ในตั้งค่าเพื่อเริ่มจากสถานะสะอาด
